# FlowMouse for Safari

This directory is generated by Apple's `safari-web-extension-converter` from the
repo root's `manifest.json` and `js/`/`pages/`/`_locales/` source — it is not
hand-written and gets overwritten if regenerated.

## Regenerating

Only regenerate if the extension's manifest or top-level file layout changed in
a way Xcode needs to know about (new content script, new permission, etc.) —
day-to-day JS/CSS/HTML edits do NOT require regeneration; Xcode picks up
changes to the copied source files on rebuild.

From the repo root:

```bash
xcrun safari-web-extension-converter . \
  --project-location safari \
  --app-name FlowMouse \
  --bundle-identifier com.hmilylcg.flowmouse \
  --swift \
  --macos-only \
  --copy-resources \
  --no-open \
  --no-prompt \
  --force
```

`--force` overwrites the existing `safari/` output. Re-apply the deployment
target change (macOS 13.3) after regenerating, since the converter resets
project settings to Xcode's defaults.

**Note:** running the command above as written recurses infinitely and fails
with "File name too long", because `--project-location safari` points inside
the same tree that `--copy-resources` is copying (`.`), so the copy step keeps
re-copying its own output into itself. Work around this by pointing
`--project-location` at a directory *outside* the repo (e.g. a scratch/tmp
directory), then moving the generated `FlowMouse/` folder produced there into
`safari/FlowMouse` in the repo:

```bash
xcrun safari-web-extension-converter . \
  --project-location /tmp/flowmouse-safari-build \
  --app-name FlowMouse \
  --bundle-identifier com.hmilylcg.flowmouse \
  --swift \
  --macos-only \
  --copy-resources \
  --no-open \
  --no-prompt \
  --force

rm -rf safari/FlowMouse
mv /tmp/flowmouse-safari-build/FlowMouse safari/FlowMouse
rm -rf /tmp/flowmouse-safari-build
```

Then re-apply the macOS 13.3 deployment target (see below).

## Deployment target

The converter defaults the generated project's `MACOSX_DEPLOYMENT_TARGET` to
whatever the local Xcode's default is (varies by Xcode version) for the app
target, and macOS 10.14 for the extension target — both need to be raised to
**13.3** to match the Safari 16.4+ floor from this extension's global
constraints (the minimum version with the MV3 service-worker background and
`chrome.storage.session` APIs this extension already relies on on
Chrome/Edge). After regenerating, either:

- In Xcode: select the `FlowMouse` project → each target (`FlowMouse` app and
  `FlowMouse Extension`) → Build Settings → set **macOS Deployment Target** to
  **13.3** for both Debug and Release, or
- From the command line: find every
  `MACOSX_DEPLOYMENT_TARGET = <value>;` line in
  `safari/FlowMouse/FlowMouse.xcodeproj/project.pbxproj` and change
  `<value>` to `13.3` (there is one per build configuration × target, so
  typically 4 occurrences: Debug/Release × app/extension).

## Building and running

1. Open `safari/FlowMouse/FlowMouse.xcodeproj` in Xcode.
2. Select the `FlowMouse` (macOS app) scheme, build and run (⌘R). This
   launches a thin host app whose only job is to register the extension with
   Safari.
3. In Safari: Settings → Extensions → enable "FlowMouse".
4. If gestures don't respond on a page, check Safari's per-site permission for
   the extension (Settings → Extensions → FlowMouse → allow on the site you're
   testing, or "Allow on All Websites").

Building requires your own Apple Developer signing identity, configured in
Xcode's Signing & Capabilities tab for both the app and extension targets —
this repo does not (and should not) ship one.

## Minimum version

Safari 16.4 / macOS 13.3. Earlier versions lack MV3 service-worker background
scripts and `chrome.storage.session`, both of which this extension already
requires on Chrome/Edge.
